# 스레드(Threads) 자동 홍보 게시

2026-11-12 사용자 결정: 북한 도발 뉴스가 떠서 사람들이 관심을 가질 때마다 스레드에 홍보 글을 자동으로 올린다. 코드는 `src/core/threads.ts` 한 곳.

## 무엇이 언제 올라가나 (2026-11-16 사용자 결정: 담백하게, 오글거리지 않게)

| 종류 | 언제 | 무엇 |
|---|---|---|
| ① 앱 소개 | 네이버 전쟁 불안 검색이 평소(직전 28일 중앙값)의 **1.5배** 이상인 날 (하루 한 번 11:41 확인, `THREADS_SEARCH_MIN`) | 소개 글 + 예시 화면 2장(넘겨 보기) + 주소 |
| ② 큰 뉴스 | 운영자 사건 알림이 나간 **북한 발사·포격·경보 사건** (사건 하나에 한 번) | 무슨 일인지 한 줄 + 짧은 소개 + 주소 |

- 둘이 합쳐 하루 `THREADS_DAILY_MAX`(기본 3)번, 글 사이 2시간.
- 훈련·정정·논평 기사·확인 안 된 단일 보도는 올리지 않는다. 공식 발표를 인용한 속보는 "(속보, 아직 확인 중)"을 붙인다.
- 시험 서버에서는 올라가지 않는다(토큰을 넣지 않고 크론도 없다).

### 넣지 않는 것

- **우리 판정**(단계·%·어제 대비·검색 배율) — 결제한 손님이 받는 정보다. 스레드에 다 적으면 살 이유가 없다(11/16 사용자). 검색 배율은 올리는 때를 고르는 데만 쓴다.
- 손님인 척하는 후기, 없는 적중 사례, "안 울리면 안전" 같은 장담, 공포를 부추기는 말(테스트가 확인).

### 문장

`src/core/threads.ts` 의 `INTRO_TEXTS`(소개 4개, I1~I4)·`NEWS_TEXTS`(뉴스 3개, N1~N3)를 차례로 번갈아 쓴다. 같은 글이 되풀이되지 않게 하려는 것이고, 문장을 그때그때 지어내지 않는다(사람이 보지 않고 공개된다). 문장을 바꾸거나 더하려면 이 두 목록만 고친다. 신호 수(`SIGNAL_COUNT` 39)는 웹사이트 첫 화면과 같아야 한다(테스트).

### 예시 화면

`/promo/1.jpg`(알림함)·`/promo/2.jpg`(그때의 대시보드) — 3단계로 올라간 알림이 왔을 때의 모습을 실제 화면 코드로 그린 것(`src/worker/promo.ts`). 맨 위에 **"예시 화면 · 실제 상황이 아닙니다"** 띠가 있다. 사진만 퍼지면 가짜 위기 소식이 되므로 띠를 빼지 않는다. 결제 코드 같은 개인 정보는 넣지 않는다. 사진 올리기에 실패하면 글만 올린다.

## 켜는 법 (한 번)

1. 스레드에 홍보용 계정을 만든다.
2. https://developers.facebook.com 에서 앱을 만들고 사용 사례로 **Threads API** 를 고른다. 권한 `threads_basic`, `threads_content_publish`.
3. 앱 역할 → **Threads 테스터**에 홍보 계정을 넣고, 스레드 앱(설정 → 계정 → 웹사이트 권한 → 초대)에서 수락한다. 자기 계정에만 올리므로 앱 심사는 필요 없다.
4. 앱 대시보드의 Threads API 설정에서 그 계정의 **사용자 토큰**을 만들고 오래가는 토큰(60일)으로 바꾼다.
5. GitHub 저장소 Secrets 에 `THREADS_ACCESS_TOKEN` 으로 등록하고 본 서버를 다시 배포한다.

토큰은 서버가 일주일마다 스스로 새로 받는다(하루 한 번 크론에서 확인). 끊기면 운영자에게 `[시스템] 스레드 자동 게시 실패` 알림이 하루 한 번 온다.
끄려면 Secret 을 지우고 다시 배포한다.

## 확인

`GET /api/threads` (운영자 비밀값): 켜졌는지, 최근 올린 글·실패 이유, 나갈 글 7개의 견본. 어느 문장이 반응이 좋은지는 기록의 `style`(I1~I4·N1~N3)·`postId` 와 스레드 앱의 조회·좋아요로 견준다.
