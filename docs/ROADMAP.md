# 정확도 로드맵 (2026-11-06 사용자와 합의)

목표: **"지금 전쟁이 어느 정도로 임박했나"를 더 잘 맞히고, 그것을 숫자로 증명한다.** 새 규칙·새 신호는 성적표에서 지금 규칙(1.0)보다 나아야만 본 서버에 들어간다.

사용자 요구(원문 요지):
- "정답(채점표) 없이 나온 %라 신뢰가 안 간다. 우크라이나·이란 같은 실제 전쟁을 연구해서 채점표가 있어야 한다."
- "나란히 비교해서 왜 정확도가 올라갔는지 알 수 있어야 2.0이 더 좋다는 걸 증명할 수 있다."
- "대시보드 열 때마다 숫자가 바뀌면 얻을 게 없다." → 오늘의 판정으로 해결(`src/core/official.ts`, 시험 서버까지 배포, 본 서버 승인 대기).

정직한 한계: 한반도에는 1953년 이후 전쟁이 없어 '전쟁 예측 정확도'를 직접 잴 수 없다. 그래서 ① 실제 전쟁이 난 외국 사례, ② 한반도의 작은 사건(큰 도발·국지 충돌), ③ 헛경보 수로 잰다.

## 1순위 — 외국 전쟁 사례집 + 채점표 (확정, 11/6 1차 완료)

**1차 결과 (11/6, `docs/CASEBOOK.md`):** 규칙 1.0 이 공격 5건 중 3건을 미리 잡음(우크라이나 32일 전, 이란 2024-04 1일 전, 2024-10 59일 전), 하마스·이스라엘↔이란 2025 는 못 잡음, 평시 헛경보 0일. 화면에 '전쟁 직전 대비 점수'(시험 서버). 재현: `npx tsx scripts/fetch-cases.ts && npx tsx scripts/score-cases.ts`.
남은 일: ① 캐나다 2022 날짜·일본 창 시작 단계 등 `.cache/cases/gt-*.json` 의 not_found ③ 못 잰 신호 — 이웃 나라 대사관 철수(2025: 6/11 이라크), 대사관 직원 이동 제한(2024-04: 4/11)이 실제 선행 신호였다 → 새 지표 후보 ④ 사례 확대(사용자와 상의) ⑤ % 보정은 아직 — `BASIS` 문장도 그렇게 적었다.

날짜·사실관계는 작업 때 출처로 다시 확인한다(기억에 의존하지 않는다). 사례 추가는 사용자와 상의.

### 사례마다 모을 것 (전쟁 90일 전 ~ 당일, 하루 단위)
우리 신호와 **같은 종류**만 모은다 — 한반도 신호를 그 나라 것으로 바꿔 끼운다.

| 우리 영역 | 사례에서 쓸 자료(예) |
|---|---|
| 정부의 행동 | 미·영 등 정부 여행경보 단계 변경일, 대사관 가족·직원 철수 명령일 (공식 발표 아카이브) |
| 돈의 움직임 | 그 나라 통화(루블·흐리우냐·셰켈·리알), 주가지수, 방산주, 유가 — 일봉 |
| 사람들의 불안 | 위키백과 문서 조회수(일별, Wikimedia API — 과거 기록 있음) |
| 예측시장 | Polymarket·Metaculus 해당 질문 가격 이력(있는 만큼) |
| 군사 동향 | 영공 폐쇄·민항기 회피(NOTAM·항공 데이터), GPS 교란(GPSJam, 2022년 이후), 위성 열점(NASA FIRMS 아카이브) |
| 언론 템포 | 보도량(GDELT 등 공개 자료) |

자료는 저장소에 `data/cases/<사례>.json` 같은 고정 파일로 남긴다(재현 가능, 출처·받은 날 기록). 큰 원자료는 저장소 밖 캐시.

### 채점 방법
- 정답: 전쟁(또는 공격) 시작일. 안 난 사례는 '아무 일도 없음'.
- 각 사례를 **지금 판정 규칙**(영역 수준 → 단계)으로 하루씩 재생한다. Worker 가 아니라 Node 스크립트로(`scripts/` — CPU 제한 없음).
- 점수:
  - **미리 잡음**: 시작일 전에 '위기(3단계)' 이상이 된 날이 있었나, 며칠 전이었나(선행일).
  - **헛경보**: 안 난 사례·평시 구간에서 3단계 이상이 된 날 수.
  - **흔들림**: 단계가 오르내린 횟수(알림 횟수).
  - 신호별로 "전쟁 전에 며칠 먼저 움직였나" 표 → 어떤 신호를 무겁게 볼지 근거.
- 1.0(지금 규칙) 점수가 기준선. 2.0은 같은 시험지로 비교하고 **차이 난 날마다 두 버전의 이유와 실제 결과**를 나란히 보여 준다.

### 화면에 반영할 것
- **전쟁 직전 대비 점수**: 0 = 한반도 평소, 100 = 우크라이나 침공 전날 수준. "지금은 실제 전쟁 직전의 몇 % 수준인가."
- 30일 % 를 사례·10년 기록으로 보정한 뒤, 화면의 "아직 채점 전" 문장(`official.ts` 의 `BASIS`)을 "OO건으로 채점한 값"으로 바꾼다.
- 성적표는 시험 서버 대시보드의 '실험 비교' 아래에 둔다(지금은 '지금 한 순간' A/B 만 있음 — `abCompare`, `dashboard.ts` 의 `abPanel`).

## 2순위 이후 (아이디어, 순서대로)

1. **헛경보 줄이기**
   - 헛경보 사후 검토 자동화: 단계가 올랐는데 7일 안에 아무 일이 없으면 "어떤 신호 때문이었나"를 기록 → 자주 헛경보를 내는 신호 목록.
   - 달력 보정: 한미연합훈련(3·8월), 북한 기념일(4/15·7/27·10/10), 당대회 같은 예정된 긴장은 평소로(10년 시험으로 검증).
   - **발사 뒤 반응 비교**(사용자 아이디어): 어제 발사가 있었다면 지난 10년 발사 다음 날들과 비교해 이번 반응이 평소 발사보다 큰가 — 큰 것만 경계로.
2. **신호마다 성적에 따라 무게** — 사례집·10년 시험에서 먼저 움직인 신호는 무겁게, 헛것을 자주 낸 신호는 가볍게.
3. **움직이는 순서를 판정에** — 정부 → 돈 → 군사 순은 진짜, 언론·검색만 먼저면 소동(지금은 '누가 먼저 움직였나'를 화면에만 보임).
4. **새 신호** (사례집에서 효과가 확인된 것만): 미 항공모함·전략폭격기 한반도 전개, 해운 전쟁보험 위험지역 지정, 북한 매체의 '전시 체제' 문구, 중국 쪽 움직임(외교부 수위, 단둥 교역).
5. **AI 분석관에 반론 의무** — 분석마다 "전쟁 징후가 아닐 수 있는 이유"를 쓰게.
6. **확률 보정** — "15%라고 한 날들 중 실제로 몇 %에서 일이 났나"(데이터가 쌓인 뒤).
