# 스레드(Threads) 자동 홍보 게시

2026-11-12 사용자 결정: 북한 도발 뉴스가 떠서 사람들이 관심을 가질 때마다 스레드에 홍보 글을 자동으로 올린다. 코드는 `src/core/threads.ts` 한 곳.

## 언제 올라가나

- 운영자 사건 알림이 실제로 나간 **북한의 발사·포격·경보 사건**(새 사건, 또는 확인 단계가 오른 사건)에만. 사건 하나에 한 번.
- 훈련·정정·논평 기사·확인 안 된 단일 보도는 올리지 않는다. 합참 등 공식 발표를 인용한 속보는 `[속보·공식발표 인용]` 꼬리표를 달고 올린다.
- 하루 `THREADS_DAILY_MAX`(기본 3, wrangler.toml)번, 글 사이 2시간.
- 시험 서버에서는 올라가지 않는다(토큰을 넣지 않고 크론도 없다).

## 무엇이 올라가나

사건 한 줄 + 그 순간의 **오늘의 판정**(화면과 같은 숫자 — 단계·30일 국지 충돌 %) + 어제와 견준 말 + 주소. 틀은 네 가지를 번갈아 쓴다.

| 틀 | 성격 |
|---|---|
| A | 속보: 사건 → 지금 판정 |
| B | 차분: "이번엔 진짜인가" → 판정은 어제와 같다 |
| C | 제작기: 혼자 만든 계기판 |
| D | 질문: 그래서 얼마나 위험한가 |

사람이 보지 않고 바로 공개되므로 문장을 그때그때 지어내지 않는다 — 들어가는 사실은 수집한 사건 요약과 판정뿐이다.
**쓰지 않는 것**: 손님인 척하는 후기, 없는 적중 사례, "안 울리면 안전하다" 같은 장담(테스트가 문구를 확인한다).

## 켜는 법 (한 번)

1. 스레드에 홍보용 계정을 만든다.
2. https://developers.facebook.com 에서 앱을 만들고 사용 사례로 **Threads API** 를 고른다. 권한 `threads_basic`, `threads_content_publish`.
3. 앱 역할 → **Threads 테스터**에 홍보 계정을 넣고, 스레드 앱(설정 → 계정 → 웹사이트 권한 → 초대)에서 수락한다. 자기 계정에만 올리므로 앱 심사는 필요 없다.
4. 앱 대시보드의 Threads API 설정에서 그 계정의 **사용자 토큰**을 만들고 오래가는 토큰(60일)으로 바꾼다.
5. GitHub 저장소 Secrets 에 `THREADS_ACCESS_TOKEN` 으로 등록하고 본 서버를 다시 배포한다.

토큰은 서버가 일주일마다 스스로 새로 받는다(하루 한 번 크론에서 확인). 끊기면 운영자에게 `[시스템] 스레드 자동 게시 실패` 알림이 하루 한 번 온다.
끄려면 Secret 을 지우고 다시 배포한다.

## 확인

`GET /api/threads` (운영자 비밀값): 켜졌는지, 최근 올린 글·실패 이유, 지금 사건이 생기면 나갈 네 틀의 견본. 어느 틀이 반응이 좋은지는 기록의 `style`·`postId` 와 스레드 앱의 조회·좋아요로 견준다.
