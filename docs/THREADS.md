# 스레드(Threads) 자동 홍보 게시

2026-11-12 사용자 결정: 북한 도발 뉴스가 떠서 사람들이 관심을 가질 때마다 스레드에 홍보 글을 자동으로 올린다. 코드는 `src/core/threads.ts` 한 곳.

## 무엇이 언제 올라가나 (2026-11-16 사용자 결정: 담백하게, 오글거리지 않게)

| 종류 | 언제 | 무엇 |
|---|---|---|
| ① 앱 소개 | 앱의 % 가 **오늘 아침 판정보다 5%p 넘게** 오르고, 전쟁 전 징조·조용한 움직임이 **하나 이상 새로 켜지고**, 그 상태가 **30분** 이어질 때 (5분마다 확인, 하루 한 번) | 소개 글 + 예시 화면 2장(넘겨 보기) + 주소 |
| ③ 개발 소식 | 사용자가 "오늘 수정한 것들 스레드에 올리자"고 할 때 | 에이전트가 오늘 본 서버(main)에 올라간 변경을 담백하게 요약해 `POST /api/threads/post` 로 |
| ② 큰 뉴스 | 운영자 사건 알림이 나간 **북한 발사·포격·경보 사건** (사건 하나에 한 번) | 무슨 일인지 한 줄 + 짧은 소개 + 주소 |

- ①② 합쳐 하루 `THREADS_DAILY_MAX`(기본 3)번, 글 사이 2시간. ③은 사람이 시킨 글이라 한도를 보지 않는다.
- ① 잡음 거르기 (11/16 사용자: 신호가 많아서 잡음으로 올라가면 안 된다): % 는 항목 하나가 켜질 때마다 약 2.6%p 오른다. 그래서 (a) 5%p = 항목 두 개 이상, (b) 배경(세계 정세·검색량·시장)만 늘어난 것은 제외 — 징조나 움직임이 새로 켜져야 하고, (c) `NOISY_ITEMS` 의 항목만 켜진 것도 제외한다. 지금은 `a_nk_dark`(북한 인터넷 외부망 장애 경보 — 자주 울리고 대개 위기와 상관없다). 잡음 항목을 더하려면 이 목록만 고친다.
- ① 은 5분 계산값(`warRisk.live`)을 오늘 아침 판정(`risk:official` 의 근접도)과 견준다. 글에는 % 나 단계를 쓰지 않는다 — 올리는 때를 고르는 데만 쓴다.
- 훈련·정정·논평 기사·확인 안 된 단일 보도는 올리지 않는다. 공식 발표를 인용한 속보는 "(속보, 아직 확인 중)"을 붙인다.
- 시험 서버에서는 올라가지 않는다(토큰을 넣지 않고 크론도 없다).

### 넣지 않는 것

- **우리 판정**(단계·%·어제 대비) — 결제한 손님이 받는 정보다. 스레드에 다 적으면 살 이유가 없다(11/16 사용자).
- 손님인 척하는 후기, 없는 적중 사례, "안 울리면 안전" 같은 장담, 공포를 부추기는 말(테스트가 확인).

### 주제 태그

모든 글(소개·뉴스·개발 소식)에 스레드 주제 태그 **"전쟁"** 을 단다(`THREADS_TOPIC`, 11/16 사용자). 태그 때문에 거절되면 태그 없이 다시 올린다. 정해 둔 문장에는 모두 "전쟁"이 들어간다(검색 최신 탭에 뜨게 — 테스트).

### 문장

`src/core/threads.ts` 의 `INTRO_TEXTS`(소개 4개, I1~I4)·`NEWS_TEXTS`(뉴스 3개, N1~N3)를 차례로 번갈아 쓴다. 같은 글이 되풀이되지 않게 하려는 것이고, 문장을 그때그때 지어내지 않는다(사람이 보지 않고 공개된다). 문장을 바꾸거나 더하려면 이 두 목록만 고친다. 신호 수(`SIGNAL_COUNT` 39)는 웹사이트 첫 화면과 같아야 한다(테스트).

### 예시 화면

`/promo/1.jpg`(알림함)·`/promo/2.jpg`(그때의 대시보드) — 3단계로 올라간 알림이 왔을 때의 모습을 실제 화면 코드로 그린 것(`src/worker/promo.ts`). 맨 위에 **"예시 화면 · 실제 상황이 아닙니다"** 띠가 있다. 사진만 퍼지면 가짜 위기 소식이 되므로 띠를 빼지 않는다. 결제 코드 같은 개인 정보는 넣지 않는다. 사진 올리기에 실패하면 글만 올린다.

## ③ 개발 소식 쓰는 법 (에이전트용)

사용자가 "오늘 수정한 것들 스레드에 올리자"라고 하면:
1. `git log origin/main` 에서 오늘(한국 날짜) 올라간 커밋을 읽는다. 다른 창(세션)에서 고친 것도 본 서버에 올라갔으면 여기 있다.
   개발 도중에 시켜도 된다. 다만 아직 본 서버(main)에 안 올린 변경은 쓰지 않는다 — 손님이 아직 볼 수 없다. 넣고 싶으면 먼저 본섭에 올릴지 묻는다.
   올리려면 그 세션에 `KEW_SECRET` 환경 변수가 있어야 한다(운영자 비밀값, `.mcp.json` 과 같은 것).
2. 손님이 느낄 수 있는 변화만 골라 쓴다. **형식 (11/16 사용자):** 맨 위에 날짜(`11.16`, 일기처럼) → 빈 줄 → 바뀐 것을 `- ` bullet 로 하나씩. 앱을 처음 보는 사람도 알아듣게 풀어 쓴다(11/16 사용자: 너무 짧으면 무슨 뜻인지 모른다) — "숫자"는 "전쟁 위험 숫자", "신호"는 "(환율, 비행기 수, 검색량 같은 것)"처럼. 한 bullet 은 한두 문장 . **보고하듯 개조식**으로 끝낸다 — "~수정", "~추가", "~지정", "~반영", "~개선" (11/19 사용자: "~했음·~몰랐음"은 너무 애 같다 — 스레드 글에만 해당, 사용자와의 대화 말투는 바꾸지 않는다). 바꾼 이유는 같은 줄에 짧게 붙인다. **주소는 넣지 않는다**(11/16 사용자: 부자연스럽다). 본인이 직접 쓴 것처럼 — 줄표(—)·화살표·이모지·"여러분" 쓰지 않는다. **올리기 전에 사용자에게 글을 먼저 보여 주고 "올려"를 받는다.**
   예:
   ```
   11.16

   - 분석 AI가 매번 새로 시작해 지난 판단을 모르던 문제 수정
   - 평소와 다르게 움직이는 신호(환율, 비행기 수, 검색량 등)에 이유 설명 추가
   ```
    내부 용어·파일 이름·비밀값·판정 숫자는 쓰지 않는다. 고친 게 손님에게 보이지 않는 것뿐이면 올리지 말자고 말한다.
3. 500자 안.
4. 사용자가 "올려"라고 하면 `POST /api/threads/post` (운영자 비밀값, 본문 `{"text": "..."}`)로 올리고 결과를 알린다.

## 켜는 법 (한 번)

1. 스레드에 홍보용 계정을 만든다.
2. https://developers.facebook.com 에서 앱을 만들고 사용 사례로 **Threads API** 를 고른다. 권한 `threads_basic`, `threads_content_publish`.
3. 앱 역할 → **Threads 테스터**에 홍보 계정을 넣고, 스레드 앱(설정 → 계정 → 웹사이트 권한 → 초대)에서 수락한다. 자기 계정에만 올리므로 앱 심사는 필요 없다.
4. 앱 대시보드의 Threads API 설정에서 그 계정의 **사용자 토큰**을 만들고 오래가는 토큰(60일)으로 바꾼다.
5. GitHub 저장소 Secrets 에 `THREADS_ACCESS_TOKEN` 으로 등록하고 본 서버를 다시 배포한다.

토큰은 서버가 일주일마다 스스로 새로 받는다(하루 한 번 크론에서 확인). 끊기면 운영자에게 `[시스템] 스레드 자동 게시 실패` 알림이 하루 한 번 온다.
끄려면 Secret 을 지우고 다시 배포한다.

## 반응 통계

`GET /api/threads/insights` (운영자 비밀값): 최근 올린 글 20개의 조회·좋아요·답글·리포스트·인용·공유 수. 토큰에 `threads_manage_insights` 권한이 있어야 한다 — 앱 대시보드에서 권한을 더하고 토큰을 **새로** 받아 `THREADS_ACCESS_TOKEN` 을 바꾼다(권한은 토큰을 만들 때 정해진다).

## 확인

`GET /api/threads` (운영자 비밀값): 켜졌는지, 최근 올린 글·실패 이유, 나갈 글 7개의 견본. 어느 문장이 반응이 좋은지는 기록의 `style`(I1~I4·N1~N3)·`postId` 와 스레드 앱의 조회·좋아요로 견준다.
